# 冷面技术梗图：画面比台词重要

## 参考图在做什么

`../assets/example-linux-kernel.png` 是本仓库的 Linux 原创生成示例。学习白底、细黑线、浅灰块体、错位承重、短旁注和少量识别符号。用户最初提供的基础设施参考图不在仓库中，不把换标签当新作品。

原图不是“手绘架构图”，也不是“歪塔加几个说笑话的人”。有的东西承受不成比例的重量，有的像临时接上去，有的远远飘在旁边。**标签只报名字，位置和待遇才是包袱。**

保留有辨识度的技术物件，不要把品牌、旧设备、源码标识一概删掉，只剩无特征方块。识别点必须与目标项目有关，不照搬原图的品牌组合和技术依赖。

## 丰富来自关系不同，不是线条多

| 可用关系 | 画法 | 前提 |
| --- | --- | --- |
| 大能力依赖小机制 | 重物明确压在微小连接件上 | 核实关系，复杂系统保留协作机制 |
| 历史兼容例外 | 主线路之外另绕细线、胶带和专用开关 | 找到具体机型、协议或旧行为的实现 |
| 危机时的粗暴处理 | 评分牌旁边挂一把小锯子 | 核实触发条件和处理对象，不画随机故障 |
| 高精度服务于无事发生 | 精密计时器对着空凳或空槽 | 必须真有相应空闲、等待或跳过路径 |
| 可选/附加功能 | 偏挂的盒子、延长杆、远离主塔的小附件 | 不误画成所有路径必需的地基 |

这是选材方向，不是每张必须集齐的清单。没有特殊事实就减少看点，不编造贡献者困境、事故、性能数字或行业关系。

让主要灰色质量块远大于承重件，侧面留下白纸。造型错位、笨拙、不对称：一处倾斜，一处悬挂，一处绕行，而非均匀楼层。部件大小是夸张，不代表代码行数、性能或重要性的定量比较。

**默认没有气泡对白、小人表演、大标题或“全靠这玩意”。** 人物只在物件无法替代时出现。用极少点色，不靠木架、飞纸、排线、汗滴和装饰齿轮制造忙碌感。

## Linux 选材的事实边界

- `struct list_head` 的 `next/prev` 适合作为细小连接件。它用于任务等列表，但不是 Linux 唯一数据结构或整个调度算法。类型定义在 `include/linux/types.h`，操作在 `include/linux/list.h`。保留其他支撑或限定所画范围。
- `play_idle_precise()` 的高精度计时对应空闲注入，不是全部 CPU 调度。可画计时器与空凳，不应画成所有功能靠它执行。
- idle task 的“不能 sleep”指不能像普通任务那样阻塞出队，**不是 CPU 不能进入节能休眠**。
- OOM 通常按资格和评分选择任务，另有配置与特殊路径。不要画骰子，或写“永远杀占内存最大的进程”。
- MacBook5 有特定 x86 重启处理。专用按钮/胶带是兼容分支的比喻，不表示所有 Mac 都坏或需要外接按钮。

这些是示例选材，换版本或项目仍须重查。不要把源码注释中的术语按字面误读成错误原理。

## 出图检查

先看几何关系，再读标签：小支点若悬空，旁注再好也救不回来。检查旁梗是否真的处于特殊处境，而非贴功能名。最后核对源码标识和条件边界。

用户要求重看原图时，实际重看。对照轮廓、空白、标签语气和关系差异；一次只修发现的问题。不能用“更丰富”“更有梗”代替可执行修改，也不能用自评分数代替用户判断。
