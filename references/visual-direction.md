# 手绘荒诞技术漫画：构图与提示词

## 参考图的可复用部分

`../assets/example-cpyref-v2.png` 是本仓库的原创生成示例，用它理解白底、黑线、灰色填面、歪斜叠放、短旁注，以及把软件依赖画成物理承重关系的做法。

保留这种表达方式，为每个项目创作新的装置。不要继承参考图中的具体品牌、人物、文字或技术依赖。

## 一眼能懂的画面

先让人看见巨大而复杂的装置，再发现小得离谱的支点；随后在左右留白发现小人物的荒唐动作、冷幽默旁注和技术彩蛋。**信息量、机械零件数量和笑点密度是三件不同的事。**

| 画面部位 | 画什么 | 表达什么 |
| --- | --- | --- |
| 巨大上部 | 通常 3–5 个相互连接的功能模块，按实际功能多少调整 | 用户看见的能力；小工具可只画一个巨型外壳 |
| 狭窄连接处 | 一个小摇柄、分岔开关、垫片、小抽屉或纸盒 | 已查证的朴素核心机制 |
| 接触与连接 | 实际接触的支点、传动杆、输送口或管道 | 承重、驱动、分发或转换关系 |
| 侧边留白 | 弯箭头、短手写吐槽、反问和打岔 | 让读者继续发现第二层笑点 |
| 配角小戏 | 虚构小人搬巨量文件、递小票、撞上断开的线 | 用动作与反应放大实际功能的预期落差 |
| 技术彩蛋 | 挑选项目已证实的限制、错误提示或副作用 | 提供第三层会心一笑，不捏造技术事实 |

让主装置的视觉面积显著大于小机制，通常超过十倍；这是构图夸张，不是对项目规模的定量描述。小机制仍须足够大，能看清形状和标签。不要为了“小”把关键内容缩成一个像素。

对“驱动”笑话画运动线，对“承重”笑话画倾斜和重心，对“分发”笑话画入口和出口；不要把所有关系都画成一座单柱高塔。上方物件可故意显得不合比例、凑合而成，侧边用不同尺度的小戏回应主场景。

## 笑点编排：3 秒、10 秒、30 秒

- 3 秒：巨大塔压在一只微小抽屉上，这个主梗不读字也成立。
- 10 秒：至少两个小角色各自干一件傻事，形成冲突或反转。例如甲抱着厚厚文件求重传，乙只甩过去一张引用编号；这只是交互比喻。
- 30 秒：一个事实支持的限制被诚实而刻薄地写在旁边，例如“跨机？自己搬”“省 Token？不保证”，前提是对应项目真的如此。

每个旁梗要有动作、表情和指向明确的短字。允许几处有来源的技术符号或生态标识，以及一个出乎意料的小角色；不要为了模仿参考图而搬用无关品牌、受保护角色、编造人物贡献或作者遭遇。优先让旁梗围绕同一机制，而不是四个随机网络段子。

画法偏向笨拙的细线纸上涂鸦：块体看似随时要倒、比例有意失衡、部分文字沿边竖写或斜写、手绘箭头绕路。**禁止用高密度阴影、正确的工程透视、复杂硬表面细节来冒充“丰富”。** 白纸面积要足够让侧边小戏呼吸。

## 可借鉴的笑话语法

以下只是虚构的视觉例子，不代表任何实际项目；每次必须重新查证。

- 调度器：堆满仪表和管道的任务工厂，由一只“取出下一件”的小摇柄推动。
- 路由器：多种接口的大招牌，背后是一个“查表选出口”的小扳道器。
- 转换工具：各式输出设备接在一个寒酸模具上，旁注“按规则换个形状”。
- 状态驱动程序：巨大的自动化装置，底下小盒子内只有几张写着状态的卡片和一个拨杆。
- 需要多个机制的系统：一个小工具盒装着三个必要零件，合力支撑装置；标签写“核心套路”，不要虚构一个包办一切的单点。

不要形成固定套话：每张都写“一个 while 循环”“一个程序员”会抹掉项目差异，也容易误导。

## 图像生成提示词模板

替换所有花括号。文字清单之外不要让模型自行增加技术标签。

```text
Use case: illustration-story
Asset type: single-panel absurd engineering meme about an open-source project

项目：{准确项目名}
真实原理：{一句大白话，描述输入、关键操作和输出}
主笑点：{庞大能力与朴素核心的反差}

创作一幅原创手绘梗图，默认竖幅 2:3。纯白背景，细黑色手绘轮廓，
轻微抖动和不规整的透视，少量浅灰填色，大量侧边留白，最多两处点缀色。
它像工程师一本正经画出的离谱机器草图，粗糙但清楚，冷幽默。

画面主体：{巨大装置及实际需要的模块，通常 3–5 个；单功能时只画一个}
朴素小零件：{小零件的形状、位置与标签}
物理关系：{谁压在谁上面 / 谁带动谁 / 谁把输入分到哪里}
明确画出 {唯一关键接触点或传动连接}，使观众不读文字也能看懂反差。
小零件明显小于装置，但形状和标签仍清楚；保留完整主体和底部，不要裁切。
次级笑点 A：{来自真实工作流冲突的动作 + 表情 + 极短对白}
次级笑点 B：{来自真实限制的荒唐动作 + 极短吐槽}
技术彩蛋：{已核实的边界或错误处理；事实不足则删除本行}

准确绘制以下文字，简短、清楚、略带手写感：
- 标题："{项目名}"
- 大模块标签：{按实际功能列出逐字标签，不为凑数量增加功能}
- 其他已核实模块标签：{如无则删除本行}
- 小零件标签："{核心标签}"
- 次级短旁注："{旁注1}"、"{旁注2}"（不足则减少）
用弯曲的细箭头把标签指向对应物体。除此之外不要增加文字。

参考图角色：仅供手绘线条、黑白灰、留白与荒诞物理关系参考；
重新设计装置，不复刻参考图的构图、品牌、角色和文字。
夸张尺寸和处境，不改变上述技术因果关系。

避免：公司宣传页、整齐模块网格、精致等距插画、3D 渲染、科技蓝、
工业级透视、精密机械堆、密集排线、大面积渐变、复杂背景、过多配色、随机梗拼贴、乱码、
无依据的功能、悬空且无连接的主支点、非用户要求的作者水印。
```

## 一次修改的写法

优先指出一个具体错误，同时锁定正确的部分，例如：

> 保留白底黑线、所有模块和已有标签。只把底部的小队列盒移到承重接触点，让上方平台明确压在盒子上；盒子面积稍加大，确保标签可读。不要增加其他元素。

不要只说“更好看”“更有梗”。如果画面漂亮却没笑点，先修正大小反差，再添加至少两处有动作和反应的小场景；不要通过增加齿轮、纸张和阴影来凑丰富。
